# Status, 29 October 2026

Where the project stands, what was finished today, and what only the owner can do next.
If this file and `docs/DESIGN.md` disagree, the design wins.

## The code is complete and green

`python -m scripts.check_test_gate` passes (24 test modules, 5269 tests collected) and
`python -m pytest` passes with no network and no credentials. Every module named in the
design contract (section 12) exists and is tested. The scheduled run on GitHub reaches the
scrape step every day: the checkout, install, test gate and test suite are all green there.

## Why the daily run is red

The last three scheduled runs (27, 28 and 29 October) failed at "Scrape registries and sync
the sheet" with **exit code 2** after about a minute. Exit 2 is a setup failure before any
work. Running the job locally with no secrets set reproduces it exactly, and the code's own
message is:

> setup failed, so nothing was done and there is no sheet to write a run log to: cannot open
> the spreadsheet (SheetError: no Google credentials: set GCP_SERVICE_ACCOUNT_KEY ...)

So the repository secrets `GCP_SERVICE_ACCOUNT_KEY` and `SPREADSHEET_ID` have not been
created yet (or the sheet is not shared with the service account). No code change can fix
this; it is the one-time setup in `setup_google_sheets.md`, sections 1 to 4 and 6.

## Finished today

- `.github/workflows/tests.yml`: the test gate and the suite now run on every push and pull
  request to `main`, with no secrets. A broken commit is caught when it is pushed, not at the
  next morning's run.
- `.github/dependabot.yml`: weekly pull requests for Python dependencies and GitHub actions.
- `.github/CODEOWNERS`: the owner is asked to review any change to the workflow, the gate,
  the tests or `requirements.txt`. It takes effect once "Require review from Code Owners" is
  on in a ruleset for `main`.
- README, `docs/DESIGN.md` and `setup_google_sheets.md` updated so they no longer call these
  three things "not built".

## The owner's checklist, in order

1. **Make the daily run green**: create the Google Cloud project and service account, the
   spreadsheet, and the two secrets (`setup_google_sheets.md`, sections 1 to 4), then run the
   workflow from the Actions tab (section 6). Until then every scheduled run exits 2.
2. **Register for the Data.Dubai API** and request the "Real Estate Projects" dataset; add
   `DATA_DUBAI_API_KEY` and `DATA_DUBAI_API_SECRET` as secrets. Expect to fix column names
   on the first live run (README, "Known limitations", item 1). Then set the repository
   variable `REQUIRE_SOURCES` to `dld_projects`.
3. **Geocoding**: set the `GEOCODE_CONTACT` secret (the public OpenStreetMap geocoder asks
   for a contact), or add a `LOCATIONIQ_API_KEY` or `GEOAPIFY_API_KEY` secret for a much
   faster backfill.
4. **Get the Dubai Land Department data licence in writing** before the first public deploy.
5. **Publish the map**: set the Pages source to "GitHub Actions" and create the repository
   variable `DEPLOY_MAP` = `true` (`setup_google_sheets.md`, section 10). The first deploy
   happens on the first run that has at least one located project.
6. **Repository settings** (section 9): a ruleset on `main` with reviewed pull requests and
   "Require review from Code Owners"; optionally a hashed lock file.
7. **Decide the rest**: whether to test the Sharjah list once (`ENABLE_SRERD`), who keeps the
   seed CSV, which licensed source (if any) supplies prices, and the code licence.
